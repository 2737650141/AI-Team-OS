# AI Team OS 项目章程（草案）

> 文档状态：Phase 0 草案，待总管验收
> 版本：v0.1（2026-08-04）

## 1. 项目愿景

让用户用一句话提出目标，AI Team OS 自动完成从意图理解、记忆检索、计划制定、专家智能体分工执行、事实与产物审查、失败定向返工，到成本与证据全程记录的完整闭环——一个可长期扩展的 AI 智能体协作团队平台。

## 2. 用户问题

当前使用 AI 完成任务存在以下痛点：

- **碎片化**：每个任务都要手动挑选工具、写提示词、搬运上下文，跨任务无记忆。
- **无状态**：任务中断后无法从断点恢复，重复消耗 Token 与时间。
- **不可信**：产出缺乏可追溯的证据链，幻觉无法定位，返工靠人工重新从头再来。
- **不可控**：没有预算上限、权限分级与人工审批，危险操作无法拦截，成本不可预测。
- **不可复用**：组织过程资产（方法论、项目上下文、用户偏好）无法沉淀。

## 3. 目标用户

- **独立开发者 / 技术创业者**：需要 AI 团队完成 GitHub 技术调研、需求分析、架构设计与实施计划。
- **小型技术团队**：需要统一的 AI 协作平台承接项目前期工作，并把记忆与偏好沉淀为团队资产。
- **AI 重度用户**：希望把多个 AI 能力（调研、写作、代码、审查）编排成一条可控流水线。

MVP 面向以上用户的自托管场景（Docker Compose 单机部署起步）。

## 4. MVP 使用场景

1. **GitHub 项目研究与技术选型**：给定主题或候选仓库，产出对比矩阵与选型建议（含证据链接）。
2. **项目需求分析**：从模糊想法出发，经澄清对话产出需求规格。
3. **软件架构设计**：基于需求与约束产出架构文档（含图）。
4. **代码实施计划**：基于已有代码库产出里程碑化的实施计划。
5. **文件与文档处理**：对本地文件做摘要、分析、转换（只读 + 沙箱内写）。
6. **多智能体任务分工执行**：Planner 拆解、多个 Specialist 并行/串行执行、Reviewer 审查、失败定向返工。
7. **项目级记忆与用户偏好检索**：跨任务复用项目上下文与用户偏好。
8. **工具权限与人工审批**：高风险操作必须人工确认后放行。

## 5. MVP 范围（做）

- 后端：FastAPI + LangGraph 编排 + Pydantic 模型。
- 五角色常驻池：Supervisor / Planner / Researcher / Executor / Reviewer（可注册扩展 Specialist）。
- 统一状态模型与 LangGraph Checkpoint 持久化（M0-M3 一律 SQLite；PostgreSQL 于 M4 或出现多实例/复杂查询刚需时引入）。
- Tool Gateway：普通 Python 工具 + MCP 工具统一接入；权限分级（`risk_level: safe|sensitive|dangerous` + `read_only`）；高风险审批。
- Model Gateway：OpenAI-compatible Provider Adapter（默认 OpenAI，可配置兼容端点）。
- Memory Service：项目级记忆与用户偏好（MVP 以文件 + SQLite 起步，pgvector 向量检索延后）。
- 结构化运行日志（JSONL），预留 OpenTelemetry 接口。
- SSE 实时输出；最小管理界面（任务创建/进度/结果/审批）。
- 预算控制：每任务 Token / 成本预算，超限降级。
- 黄金任务评测集（12+ 个场景）与 pytest 测试。

## 6. 非目标（MVP 不做）

- 安卓系统级控制、Windows 全自动桌面操作、语音唤醒。
- 无限制自主运行（所有任务有明确边界与审批点）。
- 自动发送邮件、发布内容、执行支付、删除文件、修改系统配置（此类工具在 MVP 一律不提供，或仅存在于沙箱）。
- 复杂低代码工作流可视化编辑器。
- 多租户 SaaS 化、集群部署、云托管。
- 实时音视频多模态。

## 7. 成功指标

| 类别 | 指标 | 目标 |
| -- | -- | -- |
| 任务完成 | 黄金任务自动验收通过率 | ≥ 9/12 |
| 成本控制 | 预算内完成率（未超预算完成任务占比） | ≥ 90% |
| 可靠性 | 无无限循环（全部任务在步数上限内终止） | 100% |
| 可信度 | Reviewer 驳回→定向返工→验收通过链路成功率 | ≥ 80% |
| 恢复能力 | 中断任务从 checkpoint 恢复成功率 | ≥ 95% |
| 安全 | 高风险工具未经审批执行次数 | 0 |
| 证据 | 每个最终结论附带 ≥1 条可追溯证据 | 100% |

## 8. 核心约束

- 单一编排核心（LangGraph），禁止多框架并列。
- 确定性代码负责安全与预算，LLM 不拥有安全决策权。
- 所有模型调用经过 Model Gateway 统一记账；所有工具调用经过 Tool Gateway 统一鉴权。
- 状态经 LangGraph 状态机与权威写入路径写入；LLM 输出须经 Schema 校验后才能写入 RuntimeState（见 STATE_MODEL.md）。
- 默认只读优先：写操作工具必须显式声明并分级。
- MVP 单机 Docker Compose 部署，不引入不必要组件（Redis 延后）。

## 9. 高风险功能

1. 代码/命令执行沙箱（逃逸风险）——MVP 默认不提供任意命令执行；先做"沙箱内受限执行"，M3 前保持禁用。
2. 外部发布类工具（邮件/推送）——MVP 不实现。
3. 自动写用户项目文件——默认仅写沙箱工作区，写真实仓库需审批。
4. 长期自主运行——MVP 每个任务有硬性步数/时长上限。
5. 记忆自动写入——写入前需经确定性规则 + 人工确认（MVP）。

## 10. 后续扩展方向

- 移动端/桌面端入口；安卓系统级控制（远期）。
- 复杂低代码工作流编辑器；可视化图编排。
- 多模型混合编排（Planner 用强模型、批量执行用廉价模型）。
- 企业级多租户、审计合规、SSO。
- 本地小模型（Ollama）与离线模式。
- 语音交互。
- 更丰富的 Specialist 池（设计、测试、运维、文档等，按注册机制扩展而非默认常驻）。
