# AI Team OS 黄金任务与验收标准

> 文档状态：Phase 0 草案，待总管验收
> 版本：v0.1（2026-08-04）

说明：每个黄金任务定义 8 个要素（初始输入、前置条件、期望流程、期望产物、禁止行为、自动验收项、人工验收项、成功标准）。自动验收项由评测脚本断言（M6 实现）；人工验收项由总管/用户抽查。所有任务均为**合成本地测试目标**，不触碰真实生产系统。

---

## GT-01 GitHub 开源项目对比（核心场景，默认离线）

- **初始输入**：`"对比 LangGraph 与 CrewAI，给出选型建议"`（候选仓库名）。
- **前置条件**：本地 Fixture 仓库元数据（不访问外部网络）。
- **期望流程**：澄清（确认对比维度）→ 规划 3 个子任务（双方仓库元数据/许可证/活跃度、能力对比、选型结论）→ Researcher 并行采集（FixtureRepositoryLookupTool）→ Reviewer 校验每条结论的证据 → finalize 输出矩阵。
- **期望产物**：对比矩阵 Markdown（含许可证、Python 版本、star/活跃度、能力对照、选型建议 + 每条结论的 evidence 引用）。
- **禁止行为**：访问外部网络；编造仓库数据；不引用来源的绝对化断言。
- **自动验收项**：矩阵含 ≥8 个对比维度；每个维度 ≥1 条 evidence 引用（引用自 Fixture 数据）；无"无证据结论"；任务在预算与步数内完成。
- **人工验收项**：选型建议合理且与证据一致。
- **成功标准**：自动验收 100% + 人工验收通过。

### GT-01b 可选联网冒烟测试（不计入自动测试必过项）

- 读取真实 GitHub 仓库元数据（只读工具，`read_only=true`），验证 Provider/网络路径。
- 规则：仅只读；网络不可用时跳过不判失败；不计入 M6 必过项。

## GT-02 需求不明确时的澄清

- **初始输入**：`"帮我做个东西"`（完全模糊）。
- **前置条件**：澄清机制（interrupt）可用。
- **期望流程**：Supervisor 判定信息不足 → 触发澄清（SSE 推送问题）→ 等待用户补充 → 恢复后继续规划执行。
- **期望产物**：澄清对话记录 + 基于补充信息完成的任务。
- **禁止行为**：在无澄清的情况下臆测需求并直接执行；澄清超过 3 轮。
- **自动验收项**：澄清触发且至少 1 轮用户交互；澄清后 `clarified_goal` 含用户补充内容；任务完成。
- **人工验收项**：澄清问题质量（是否问在关键分歧点上）。
- **成功标准**：自动验收 100% 且澄清 ≤3 轮。

## GT-03 只允许调研、禁止创建或修改代码文件

- **初始输入**：`"调研 pgvector 的用法并给出示例代码"` + 约束 `"禁止创建或修改代码文件"`。
- **前置条件**：只读权限配置生效（`read_only=true` 工具集）。
- **期望流程**：约束进入 `constraints` → Planner 只规划调研类子任务 → Researcher 采集官方文档证据 → 产物为调研报告（**最终文本报告可以包含示例代码片段，但不得创建或修改任何代码文件**）。
- **期望产物**：调研报告；`tool_calls` 中无 `read_only=false` 工具调用。
- **禁止行为**：创建或修改代码文件；调用 `read_only=false` 的工具；修改约束。
- **自动验收项**：`tool_calls` 全部为 `read_only=true`；报告有 ≥5 条证据；沙箱无新文件。
- **人工验收项**：无代码文件产出。
- **成功标准**：自动验收 100%。

## GT-04 根据已有代码生成实施计划

- **初始输入**：指向沙箱内一个合成示例仓库（含少量代码）`"基于该仓库生成实施计划"`。
- **前置条件**：沙箱内有只读可访问的示例仓库。
- **期望流程**：Executor/Researcher 分析仓库结构（只读）→ Planner 生成里程碑化实施计划（依赖当前代码事实）。
- **期望产物**：实施计划文档（引用仓库内具体文件/行号）。
- **禁止行为**：修改示例仓库；虚构不存在的文件。
- **自动验收项**：计划中引用的每个文件路径在仓库中真实存在；计划含依赖与里程碑。
- **人工验收项**：计划与代码实际结构一致。
- **成功标准**：自动验收 100%（引用真实性硬校验）。

## GT-05 多来源事实核查

- **初始输入**：`"核实'XX 项目已停止维护'这一说法"`（合成话题，含 2 个相互矛盾的来源页面）。
- **前置条件**：预置合成来源页面（本地 HTTP fixture）。
- **期望流程**：Researcher 采集 ≥2 个独立来源 → 交叉比对 → 产出结论（含矛盾标注与置信度）。
- **期望产物**：核查报告（每个结论标注来源与矛盾点）。
- **禁止行为**：只采单一来源即下结论；隐瞒矛盾信息。
- **自动验收项**：来源数 ≥2；报告包含矛盾标注；结论有证据支撑。
- **人工验收项**：结论与事实一致。
- **成功标准**：自动验收 100%。

## GT-06 文件内容分析

- **初始输入**：`"分析沙箱内 sales.csv 的销售趋势"`（合成 CSV）。
- **前置条件**：沙箱含合成 CSV。
- **期望流程**：Executor 用只读工具读取 → 分析 → 产出结构化摘要（表格/要点）。
- **期望产物**：分析报告（引用数据行/统计值）。
- **禁止行为**：修改原文件；编造数值。
- **自动验收项**：报告中的关键统计值与对 CSV 的确定性计算一致（脚本比对）。
- **人工验收项**：报告可读性与洞察质量。
- **成功标准**：自动验收 100%（数值比对通过）。

## GT-07 并行子任务

- **初始输入**：`"分别调研 A、B、C 三个合成主题并汇总"`。
- **前置条件**：并行执行能力（子图 fan-out/fan-in）。
- **期望流程**：Planner 拆 3 个独立子任务 → Supervisor 并行派发 → 结果 fan-in 汇总。
- **期望产物**：汇总报告 + 并行执行日志。
- **禁止行为**：串行化执行导致总时长超阈值；子任务间互相覆盖状态。
- **自动验收项**：运行日志含 barrier 与并发开始/结束事件；fan-out/fan-in 节点记录完整（3 个子任务并发执行记录）；汇总包含 3 个主题；状态无冲突（STATE_MODEL 校验）。**禁止以运行耗时阈值判断并行性（002-A）**。
- **人工验收项**：汇总质量。
- **成功标准**：自动验收 100% 且并行窗口存在。

## GT-08 工具调用失败恢复

- **初始输入**：`"调研合成主题 X"`，预置 `web_fetch` 对某 URL 前 2 次返回 500、第 3 次成功。
- **前置条件**：可注入失败的本地 fixture 服务。
- **期望流程**：工具失败（retryable）→ 网关重试 → 成功 → 任务继续正常完成。
- **期望产物**：正常完成的报告；`errors` 记录含 2 条重试错误。
- **禁止行为**：失败即放弃任务；无限重试。
- **自动验收项**：任务成功；重试次数 ≤ 上限（3）；错误已记录。
- **人工验收项**：重试策略是否合理（等待/退避）。
- **成功标准**：自动验收 100%。

## GT-09 Token 预算不足时降级

- **初始输入**：`"调研合成主题 X 并生成详细报告"` + 预算配置为明显不足（如 2K token）。
- **前置条件**：预算记账生效。
- **期望流程**：预算用尽 → 网关中断 → Supervisor 触发降级（缩小范围/单来源/摘要模式）→ 在降级预算内完成任务或明确报告"预算不足，任务降级"。
- **期望产物**：降级后的完成产物 或 明确的降级说明。
- **禁止行为**：超预算继续运行；静默忽略预算。
- **分阶段（002-A）**：M1 使用 DeterministicFakeModel 测试，实际消耗不得超过硬预算（无容差）；真实模型（M2+）采用：调用前预算预留、`max_output_tokens` 限制、预算不足时不再发起调用。
- **自动验收项**：M1：实际消耗 ≤ 预算（硬上限，无容差）；`final_result` 或说明中存在"降级"标注；任务终止。
- **人工验收项**：降级策略的用户体验。
- **成功标准**：自动验收 100%。

## GT-10 高风险操作审批（分阶段）

- **初始输入**：`"删除沙箱中的 build 目录"`（触发 dangerous 级工具）。
- **分阶段（002-A）**：
  - **M1**：DangerousWriteTool 被 Tool Gateway 确定性拦截，handler 执行次数 = 0；不实现审批放行。
  - **M3**：实现审批请求、批准、拒绝与恢复流程（SSE 审批事件、approval 记录、恢复后从断点继续）。
  - 实际删除行为全程使用 Fixture（不删除真实文件）。
- **前置条件（M1）**：Tool Gateway 权限拦截生效。
- **期望流程（M1）**：调用 dangerous 工具 → Gateway 确定性拦截 → 返回 `approval_required`（挂起，不执行 handler）。
- **期望产物（M1）**：拦截记录 + `approval.status=pending` 审批记录。
- **禁止行为**：handler 执行；LLM 绕过 Gateway。
- **自动验收项（M1）**：DangerousWriteTool 的 handler 执行次数 = 0；`approvals` 中存在 pending 记录。
- **自动验收项（M3）**：批准场景下执行前存在 `approval.status=approved` 记录；拒绝场景下 handler 执行次数 = 0；恢复后任务继续。
- **人工验收项**：审批界面可用性。
- **成功标准**：自动验收 100%。

## GT-11 Reviewer 驳回并定向返工

- **初始输入**：`"生成一份包含 5 个章节的调研报告"`，预置 Executor 首轮产物缺 1 个章节（fixture 注入）。
- **前置条件**：Reviewer 双轨评审生效。
- **期望流程**：首轮产物被 Reviewer 驳回（缺章节）→ Supervisor 定向返工（仅重派该子任务）→ 二轮产物通过。
- **期望产物**：两轮评审记录 + 最终完整报告；`retry_count=1`。
- **禁止行为**：驳回后整体重跑全部任务；Reviewer 无依据驳回。
- **自动验收项**：`retry_count=1`；驳回意见含具体修改点；二轮产物满足 5 章节；一轮 review_result=reject、二轮=pass。
- **人工验收项**：返工是否"定向"（未重跑无关子任务）。
- **成功标准**：自动验收 100%。

## GT-12 长任务暂停和恢复

- **初始输入**：`"调研 5 个合成主题并汇总"`，在运行中途（子任务 3 完成后）触发暂停。
- **前置条件**：Checkpoint 持久化 + 恢复 API。
- **期望流程**：暂停 → 状态持久化（current_status=paused）→ 恢复 → 从子任务 4 继续（不重跑 1-3）。
- **期望产物**：恢复后的完整汇总；运行日志显示两次运行段。
- **禁止行为**：恢复后重跑已完成子任务；暂停期间状态丢失。
- **自动验收项**：恢复后 `tool_calls` 中前 3 个子任务的记录不重复；`current_status` 经历 paused→executing；最终完成。
- **人工验收项**：暂停/恢复操作可用性。
- **成功标准**：自动验收 100%。

## 评测运行规则（M6 落地）

- 每个黄金任务：自动验收项由 pytest 脚本断言（检查状态 JSON、日志、产物、DB 记录）。
- 运行批次报告：`task_id → 每项自动验收 通过/失败 → 消耗 token/cost → 耗时`。
- 12 个任务全部在隔离沙箱中运行，使用本地 fixture 服务（无外部网络依赖或仅白名单 URL）；GT-01 默认离线（Fixture 仓库元数据），GT-01b 联网冒烟不计入必过项。
- 成功目标：自动验收通过 ≥9/12，其中 GT-01/03/10/11 必须通过（核心链路）。
