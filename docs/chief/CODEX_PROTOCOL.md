# CODEX_PROTOCOL

> 长期稳定工作规则（约 120 行内）。这是唯一需要长期遵守的协议文件；
> 过去的临时总管令已过期，不要复制或引用。

## 1. Root Cause First

- 任何失败先找根因（代码路径 + 数据证据），禁止表面修复或绕过。
- 复现失败：相同用户输入 + 真实运行路径；无法复现则明确说明假设。
- 修复后用同一输入重放验证根因已消除。

## 2. Minimal Change

- 只改解决问题所需的最小范围；不顺手重构无关代码。
- 不新增功能、不扩张范围，除非任务明确要求。
- 改动前先看周边行为，避免破坏既有契约。

## 3. Targeted Test First

- 先写能复现失败的针对性测试（红色），再修代码（变绿）。
- 禁止删除/跳过/禁用失败测试来换取绿色。
- 修复的验证 = 针对性测试 + 受影响模块，不必要不做全量回归。

## 4. No Blind Retry

- 连续两次相同失败即停止盲重试：换方法、换计划或上报。
- 重试必须带进展（不同方法/修正参数），禁止无变化重试。
- 运行时对 rework 无进展必须走 replan，而不是无限循环。

## 5. No Unnecessary Full Regression

- 小改动验证目标模块即可；只有改动横跨多模块/核心链路才跑全量。
- 全量回归是交付门禁，不是每次提交的默认动作。

## 6. No Benchmark Hardcoding

- 禁止针对测试题/验收题硬编码答案、路径或行为分支。
- 验收/基准用真实用户任务与真实运行路径，变体必须轮换。
- 测试里出现任何"只有这道题能过"的逻辑都算违规。

## 7. Security / Test / Evidence Priority

- 安全 > 正确性 > 便利。不做不安全的最小改动。
- 不暴露密钥：凭据只经 SecretResolver→系统凭据库，绝不硬编码/打印/入库明文。
- 结果必须带证据链（claims→evidence），无证据的结论不算完成。
- UI 失败必须可解释：阶段/原因/错误码/可重试/已做恢复。

## 8. Stop When Validated

- 达到验收标准即停，不追求完美主义扩张。
- 验证完成的标志是明确的门禁通过 + 可复现证据，不是测试数量。
- 测试数量、代码行数、功能数量都不是质量证明。

## 9. Open-Source Only When Needed

- 只在明确需要时引入外部开源依赖；优先内部实现与既有依赖。
- 引入前做许可/安全审查（见 docs/research/ 的既有审查记录）。
- 不复制第三方代码进本项目而不注明来源。

## 10. Protect User Changes

- 用户已验收/已提交的实现是基线，不得擅自回退或重构。
- 未提交改动先保护（checkpoint commit）再继续其他工作。
- 会话收口时确保工作区干净、交付物入库。

## 11. Never Expose Secrets

- API key/token/凭据一律走系统凭据库（Windows Secure Store / SecretResolver）。
- 日志、报告、diff、错误消息中不得出现密钥明文（打码）。
- 环境变量只作配置开关，不作唯一凭据入口。
